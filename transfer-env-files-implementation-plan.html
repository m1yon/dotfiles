transfer-env-files Implementation Plan

Build a shared Bun CLI that pulls project-local .env files from an old machine's GitHub workspace into the current machine's GitHub workspace, creating missing directories and skipping existing local secrets by default.

Shared Bun CLI SSH + rsync Secrets-aware defaults No global installs

Target Behavior

Run this on the new/current machine: 

transfer-env-files old-mac.local
transfer-env-files michael@192.168.1.50 --dry-run
transfer-env-files old-linux --remote-root ~/github --local-root ~/GitHub --overwrite
  • Source machine is the positional SSH target, such as old-mac.local, old-linux, or michael@192.168.1.50.
  • Remote workspace defaults to ~/GitHub if present, then ~/github.
  • Local workspace defaults to $HOME/GitHub if present, then $HOME/github.
  • Files copied: .env and .env.*.
  • Files skipped: examples/templates such as .env.example, plus dependency/build/cache directories.
  • Existing local env files are skipped unless --overwrite is passed.

Key Decisions

Decision Plan Reason
Script scope scripts/bun/src/shared/src/transfer-env-files/index.ts Works on macOS and Linux, and matches the existing Bun script layout.
Transport rsync over SSH Preserves relative paths, creates directories, supports dry runs, and handles incremental copies.
Overwrite policy Skip existing files by default with --ignore-existing A bootstrap command should not destroy newer local secrets accidentally.
Secret handling Copy files only between machines; never commit copied env files into this repo This repo manages durable machine secrets through SOPS. Project env files remain project-local.
Package dependency Add pkgs.rsync to home/shared/packages.nix if it is not already present Pure Nix rule: runtime tools must be declared, not installed imperatively.
Important: rsync must exist on both machines. After adding it declaratively, Michael should run the appropriate rebuild on each managed machine that needs to send or receive env files.

CLI Contract

Argument or option Default Behavior
<host> Required SSH target for the source machine. Rely on ~/.ssh/config for custom ports, users, and keys.
--remote-root <path> Auto-detect ~/GitHub, then ~/github Remote workspace to scan for env files.
--local-root <path> Auto-detect $HOME/GitHub, then $HOME/github Local destination workspace. Create it if missing.
--dry-run false Print what would copy without writing files.
--overwrite false Allow remote env files to replace local env files.
--include-examples false Also copy .env.example, .env.sample, and .env.template when needed.
--verbose false Show the resolved roots and the generated rsync command without printing secret contents.

Implementation Steps

  1. Create scripts/bun/src/shared/src/transfer-env-files/index.ts as a tiny entry point with the required shebang and front matter description.
  2. Move yargs setup and input validation into cli.ts, returning a typed options object instead of running transfer logic directly.
  3. Add roots.ts for local/remote GitHub root detection and SSH/rsync preflight checks.
  4. Add rsync.ts for include/exclude filters, argv construction, command execution, and rsync summary parsing.
  5. Add transfer.ts for the high-level workflow: parse options, resolve roots, create the local root, run rsync, and print the result.
  6. Keep shared types and constants close to the file that owns the behavior; only add a separate types.ts later if duplication becomes noisy.

Module Layout

Keep the source layout to five files. This gives the main behaviors names without turning the tool into a maze of tiny modules. 

scripts/bun/src/shared/src/transfer-env-files/
  index.ts      # shebang, front matter, runCli(), error-to-exit handling
  cli.ts        # yargs parser, defaults, validation, typed options
  roots.ts      # local/remote root detection plus ssh/rsync preflight
  rsync.ts      # rsync filters, argv construction, execution, summary parsing
  transfer.ts   # high-level workflow orchestration and terminal summary
The entry point should look roughly like runCli(process.argv).catch(handleCliError). Avoid separate config.ts, process.ts, preflight.ts, summary.ts, or types.ts unless the first implementation proves they are needed.

Rsync Shape

The implementation should build argv directly and call Bun.spawn. Do not interpolate this through a shell. 

rsync \
  -a \
  --prune-empty-dirs \
  --itemize-changes \
  --stats \
  --chmod=F600 \
  --ignore-existing \
  --exclude='**/.git/***' \
  --exclude='**/node_modules/***' \
  --exclude='**/.direnv/***' \
  --exclude='**/.next/***' \
  --exclude='**/dist/***' \
  --exclude='**/build/***' \
  --exclude='**/coverage/***' \
  --exclude='.env.example' \
  --exclude='.env.sample' \
  --exclude='.env.template' \
  --include='*/' \
  --include='.env' \
  --include='.env.*' \
  --exclude='*' \
  old-mac.local:~/GitHub/ \
  ~/GitHub/
When --overwrite is passed, remove --ignore-existing. When --dry-run is passed, add --dry-run and keep every other behavior the same.

Security Guardrails

No secret output

Never print file contents. Logs should show paths and transfer summaries only.

Skip by default

Do not overwrite existing local env files unless --overwrite is explicit.

Restrictive file mode

Apply --chmod=F600 so copied env files are readable only by the current user.

SOPS boundary

Do not convert copied project env files into repo-managed secrets in this command. SOPS remains the path for durable system secrets.

Test Layout

Keep tests close to the module they describe. Integration tests should use fake command runners and temporary directories, not real SSH hosts. 

scripts/bun/src/shared/src/transfer-env-files/
  cli.test.ts        # required host, aliases, defaults, bad input rejection
  roots.test.ts      # local root selection, remote root detection, preflight
  rsync.test.ts      # include/exclude filters, dry-run, overwrite behavior
  transfer.test.ts   # workflow behavior with fake runner and tmp dirs
The highest-value tests are rsync.test.ts and transfer.test.ts, because they protect the dangerous behavior: what gets copied and whether existing files are overwritten.
