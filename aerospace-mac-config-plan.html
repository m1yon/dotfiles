AeroSpace Migration Plan for the Mac Config

Goal: make the new macOS setup feel close to the Linux Hyprland setup while keeping every package, setting, app rule, and config file declarative in this Nix flake.

Planning only No Nix config edited Nix package exists: aerospace 0.19.2-Beta User rebuild required after implementation

Executive Summary

  • Use pkgs.aerospace from the pinned nixpkgs first, not Homebrew.
  • Add a Darwin Home Manager module: home/darwin/aerospace.nix.
  • Keep the AeroSpace config in dotfiles/aerospace/aerospace.toml.
  • Symlink it to ~/.config/aerospace/aerospace.toml with Home Manager, like the Codex config.
  • Keep workspaces 1 through 10, plus M for the Spotify special-workspace replacement.
  • Use workspaces 1 through 5 as general/dev defaults with no forced app rules.
  • Use AeroSpace on-window-detected rules for default app placement.
  • Only add active app rules for apps installed now: Superhuman, Slack, Teams, and Spotify.
  • Launch workspace-managed startup apps from AeroSpace after-startup-command, not manual macOS Login Items.
  • Add a Nix-managed Login Items cleanup that removes Teams from macOS Login Items if the app re-adds itself.
  • Use commented placeholders for Linear, database apps, and other future apps.
  • Use accordion layouts on workspaces 8 and 9 to approximate Hyprland groups once those spaces have multiple apps.
  • Set macOS Mission Control defaults declaratively for better AeroSpace behavior.
Main recommendation: use alt as the AeroSpace modifier on macOS, even though Linux uses SUPER. Binding cmd-c, cmd-v, cmd-f, or cmd-r to window-manager actions would fight normal macOS app shortcuts.

Implementation Phases

  1. Create the AeroSpace Home Manager module. Add home/darwin/aerospace.nix, import it from home/darwin/default.nix, install pkgs.aerospace, and link dotfiles/aerospace/aerospace.toml into ~/.config/aerospace/aerospace.toml.
  2. Add macOS defaults for AeroSpace stability. In darwin/system.nix, add or confirm: system.defaults.dock.mru-spaces = false, system.defaults.dock.expose-group-apps = true, and system.defaults.spaces.spans-displays = true. The Spaces setting requires logout after rebuild.
  3. Port the core keymap. Start with alt as the main modifier. Keep the same letter/number layout as Linux.
  4. Port the app placement rules. Add active rules only for installed apps with confirmed bundle IDs. Keep commented placeholders for Linear, database apps, Discord, Todoist, and Chrome webapps.
  5. Launch startup apps from AeroSpace. Put apps that should be routed to workspaces, such as Teams, in after-startup-command. This makes AeroSpace start first, load the callbacks, then detect and place the app window.
  6. Remove Teams from macOS Login Items declaratively. Add an idempotent activation script in the Darwin config that deletes Teams from per-user Login Items. This prevents Teams from racing AeroSpace at login.
  7. Approximate Hyprland groups. Set workspaces 8 and 9 to accordion layouts at startup.
  8. Handle special-workspace behavior. Replace special:spotify with persistent workspace M and bind alt+m.
  9. Validate before switch, then ask Michael to rebuild. Agent can run Nix eval/check commands, but Michael runs the rebuild/switch command.

Proposed Nix Shape

This is a sketch, not an implementation patch. The TOML lives in dotfiles/; Nix only installs AeroSpace and links the file.

# home/darwin/default.nix
{
  imports = [
    ./aerospace.nix
    ./codex.nix
    ./packages.nix
    ./shell.nix
  ];
}

# home/darwin/aerospace.nix
{ config, nixConfigDir, pkgs, ... }:

let
  dotfiles = "${nixConfigDir}/dotfiles";
  outOfStore = config.lib.file.mkOutOfStoreSymlink;
in

{
  home.packages = [
    pkgs.aerospace
  ];

  home.file.".config/aerospace/aerospace.toml" = {
    source = outOfStore "${dotfiles}/aerospace/aerospace.toml";
    force = true;
  };
}
Fallback only if needed: if the Nix package does not expose the app bundle in a way macOS can launch at login, declare the upstream Homebrew tap through nix-homebrew and add the aerospace cask in darwin/homebrew.nix. Do not run brew install.

Startup App Strategy

  • Use AeroSpace after-startup-command for apps that should land on a specific AeroSpace workspace.
  • Do not add those apps manually in macOS Login Items, because they can launch before AeroSpace is ready.
  • For Teams specifically: start it from AeroSpace and remove it from macOS Login Items via Nix activation.
  • If Teams starts after AeroSpace is running, on-window-detected should move it to workspace 9.
  • If Teams starts before AeroSpace is ready, the rule may not run until callbacks are applied again.
  • Keep background-only services in declarative Nix launchd/Home Manager config instead of AeroSpace.
after-startup-command = [
  'layout --workspace 8 --root h_accordion',
  'layout --workspace 9 --root h_accordion',

  # Startup apps with workspace rules.
  'exec-and-forget open -g -b com.microsoft.teams2',
]

on-window-detected = [
  { if = 'test %{app-bundle-id} = com.microsoft.teams2', run = 'move-node-to-workspace 9' },
]

Login Items Plan

nix-darwin has system.defaults.loginwindow, but those options manage the login screen, not the per-user app list shown in System Settings -> General -> Login Items.

  • There is no clean first-class nix-darwin option that says "the complete Login Items list is exactly this set."
  • The practical Nix-managed approach is an idempotent activation script that removes known unwanted login items.
  • Use that cleanup for Teams so AeroSpace owns Teams startup and workspace routing.
  • A stricter allowlist script is possible, but it is riskier because macOS and apps also use background helper items.
# Proposed shape: darwin/login-items.nix
{
  lib,
  username,
  ...
}:

let
  loginItemsToRemove = [
    "Microsoft Teams"
    "Teams"
  ];

  removeLoginItem = name: ''
    launchctl asuser "$uid" sudo --user="$user" -- osascript -e ${lib.escapeShellArg ''
      tell application "System Events"
        if exists login item "${name}" then delete login item "${name}"
      end tell
    ''}
  '';
in
{
  system.activationScripts.removeUnmanagedLoginItems.text = lib.mkAfter ''
    echo "removing unmanaged macOS Login Items..." >&2
    user=${lib.escapeShellArg username}
    uid="$(id -u -- "$user")"

    ${lib.concatMapStringsSep "\n" removeLoginItem loginItemsToRemove}
  '';
}
Before implementation, verify the exact Login Item name with: osascript -e 'tell application "System Events" to get the name of every login item'. Keep both Microsoft Teams and Teams in the removal list if the name varies across versions.

Open Decisions

Decision Recommendation Why
Main modifier alt Preserves letter/number muscle memory without taking over core macOS cmd shortcuts.
Spotify special workspace replacement Workspace M AeroSpace has workspaces, not Hyprland special workspaces. M keeps numbered workspaces predictable.
Launcher binding Decide later: Raycast, Spotlight, or no binding Linux uses Vicinae on SUPER+Space. The Mac config does not currently declare a launcher app.
Monitor pinning Defer until after first AeroSpace run AeroSpace monitor patterns depend on real macOS monitor names/order.
Visual active window border Defer JankyBorders AeroSpace does not draw borders. pkgs.jankyborders exists, but it is extra moving part.
Workspace bar Defer SketchyBar Waybar does not apply on macOS. AeroSpace tray plus shortcuts are enough for the first pass.

Known Gaps vs Hyprland

  • No direct special workspace equivalent. Use workspace M for Spotify.
  • No Hyprland group tabs. Use AeroSpace accordion layouts for workspaces 8 and 9.
  • No Linux media/brightness commands. Let macOS handle media keys.
  • No Waybar. Defer SketchyBar until the core window workflow works.
  • No active rules for uninstalled apps. Linear, database apps, Todoist, Discord, and Calendar/webapps stay as comments until needed.

Definition of Done

  • AeroSpace is installed through Nix or declarative nix-homebrew fallback.
  • AeroSpace config is fully managed by Home Manager.
  • Core navigation and workspace movement shortcuts work.
  • Superhuman, Slack, Teams, and Spotify open on intended workspaces.
  • Teams starts from AeroSpace and is removed from macOS Login Items by Nix activation.
  • Linear/database/future app rules exist only as commented placeholders.
  • Workspaces 8 and 9 behave like grouped/stacked task and comms spaces.
  • Nix evaluation passes before Michael runs the rebuild.
  • After rebuild, AeroSpace dry-run config validation passes.
