OneDrive and SharePoint Sync Plan for macOS

Goal: add the native Microsoft OneDrive client to the Mac setup, sync the same business OneDrive and SharePoint libraries as Linux, and preserve stable script paths under ~/OneDrive.

Planning only Nix-managed install Darwin program module Keeps ~/OneDrive paths Manual Microsoft sign-in required User rebuild required

Executive Summary

  • Use Microsoft's native OneDrive for Mac app, installed declaratively from darwin/programs/onedrive.nix.
  • Keep darwin/homebrew.nix focused on Homebrew plumbing, taps, activation behavior, and any not-yet-localized apps.
  • Add darwin/programs/default.nix as the Darwin app-module import hub.
  • Let the OneDrive module own both homebrew.casks = [ "onedrive" ] and the ~/OneDrive compatibility links.
  • Do not try to port the Linux onedrive service setup directly. In this flake, pkgs.onedrive is Linux-only.
  • Let macOS and OneDrive own the real sync root under ~/Library/CloudStorage.
  • Create a compatibility directory at ~/OneDrive for scripts and repos.
  • Inside ~/OneDrive, create symlinks named personal, carecoordinators, and reporting.
  • Use SharePoint's Add shortcut to My files flow first. Use Sync only if shortcut behavior is not good enough.
  • Use Finder's Always keep on this device for folders that should behave like local clones.
Main constraint: OneDrive's actual macOS sync root is controlled by Apple's File Provider system. The plan keeps ~/OneDrive stable as a compatibility layer instead of fighting the system-owned location.

Target Path Layout

The real paths will be discovered after OneDrive is installed and signed in. Expected examples: 

~/Library/CloudStorage/OneDrive-MECA Therapies
~/Library/CloudStorage/OneDrive - MECA Therapies
~/Library/CloudStorage/OneDrive-Personal

The exact folder name depends on OneDrive's current Mac client and the tenant display name.

Compatibility path Likely target Created by
~/OneDrive/personal ~/Library/CloudStorage/OneDrive-* for the MECA work account Home Manager activation script after OneDrive sign-in.
~/OneDrive/carecoordinators A Care Coordinators shortcut or synced library inside ~/Library/CloudStorage Home Manager activation script after the SharePoint library exists locally.
~/OneDrive/reporting A Reporting shortcut or synced library inside ~/Library/CloudStorage Home Manager activation script after the SharePoint library exists locally.
Safe symlink direction: ~/OneDrive/name points into ~/Library/CloudStorage. Avoid putting symlinks inside OneDrive that point to random outside folders and expecting OneDrive to sync them.

Implementation Phases

  1. Add a Darwin programs import hub. Create darwin/programs/default.nix, import ./onedrive.nix from it, and import ./programs from darwin/configuration.nix.
  2. Create the OneDrive Darwin program module. Create darwin/programs/onedrive.nix. This module should declare the OneDrive Homebrew cask and the Home Manager activation script together.
  3. Keep OneDrive out of the central cask list. Do not add "onedrive" to darwin/homebrew.nix. That file remains the Homebrew backend and shared activation policy.
  4. Create the compatibility directory safely. The OneDrive module should create ~/OneDrive if it does not exist. If a non-directory already exists there, it should warn and leave it alone.
  5. Install and launch OneDrive through a user-run rebuild. The agent can edit the Nix files and run eval/check commands. Michael runs the rebuild or switch command.
  6. Sign in manually. Open OneDrive, sign in with the MECA account, and let it create the macOS CloudStorage root.
  7. Add the SharePoint libraries. In SharePoint or Teams, add shortcuts for Care Coordinators and Reporting to OneDrive. If shortcuts are not suitable, use the SharePoint Sync button instead.
  8. Discover exact local names. Run the discovery commands below, then update the module's target names if OneDrive used unexpected folder names.
  9. Re-run Home Manager activation. Once targets exist, the activation script creates or repairs ~/OneDrive/personal, ~/OneDrive/carecoordinators, and ~/OneDrive/reporting.
  10. Pin local copies where needed. In Finder, right-click the relevant folders and choose Always keep on this device.
  11. Verify scripts. Test scripts and repos that use ~/OneDrive. If any script assumes Linux-only URL mapping, add a Darwin branch rather than changing the shared path contract.

Discovery Commands

Run these after OneDrive has signed in and after the SharePoint libraries have been added. 

ls -la "$HOME/Library/CloudStorage"

find "$HOME/Library/CloudStorage" \
  -maxdepth 3 \
  -type d \
  \( -iname '*Care*' -o -iname '*Reporting*' -o -iname '*OneDrive*' \) \
  -print
Do not use rm -rf or manually move OneDrive's CloudStorage folders. If a bad sync root appears, fix it through OneDrive's account settings or uninstall/reset flow, then rerun the Nix activation.

Proposed Nix Shape

This is the implementation sketch. The final target names may need adjustment after discovery. 

# darwin/configuration.nix
{
  imports = [
    ./nix.nix
    ./system.nix
    ./homebrew.nix
    ./programs
  ];
}
# darwin/programs/default.nix
{
  imports = [
    ./onedrive.nix
  ];
}
# darwin/programs/onedrive.nix
{ username, ... }:

{
  homebrew.casks = [ "onedrive" ];

  home-manager.users.${username} = { config, lib, ... }:
    let
      homeDir = config.home.homeDirectory;
    in
    {
      home.activation.onedriveCompatibilityLinks = lib.hm.dag.entryAfter [ "writeBoundary" ] ''
    set -eu

    compat="${homeDir}/OneDrive"
    cloud="${homeDir}/Library/CloudStorage"

    if [ -e "$compat" ] && [ ! -d "$compat" ]; then
      echo "$compat exists but is not a directory; leaving it unchanged." >&2
      exit 0
    fi

    mkdir -p "$compat"

    find_work_root() {
      for dir in "$cloud"/OneDrive-* "$cloud"/"OneDrive - "*; do
        [ -d "$dir" ] || continue

        case "$(basename "$dir")" in
          OneDrive-Personal|"OneDrive - Personal")
            continue
            ;;
        esac

        printf '%s\n' "$dir"
        return 0
      done

      return 1
    }

    link_name() {
      name="$1"
      target="$2"
      link="$compat/$name"

      [ -e "$target" ] || [ -d "$target" ] || return 0

      if [ -L "$link" ]; then
        ln -sfn "$target" "$link"
      elif [ ! -e "$link" ]; then
        ln -s "$target" "$link"
      else
        echo "$link exists and is not a symlink; leaving it unchanged." >&2
      fi
    }

    if work_root="$(find_work_root)"; then
      link_name personal "$work_root"

      for candidate in \
        "$work_root/Care Coordinators" \
        "$work_root/CareCoordinators" \
        "$work_root/carecoordinators"
      do
        if [ -d "$candidate" ]; then
          link_name carecoordinators "$candidate"
          break
        fi
      done

      for candidate in \
        "$work_root/Reporting" \
        "$work_root/reporting"
      do
        if [ -d "$candidate" ]; then
          link_name reporting "$candidate"
          break
        fi
      done
    else
      echo "No OneDrive work/school CloudStorage root found yet; sign in to OneDrive and rerun activation." >&2
    fi
      '';
    };
}
This module lives in the Darwin layer because homebrew.casks is a nix-darwin option. It can still configure the user-level symlinks by setting home-manager.users.${username}. The activation is intentionally idempotent, so it can run before OneDrive is configured, after sign-in, and after SharePoint shortcuts are added.

Rollback

  1. Remove the ./onedrive.nix import from darwin/programs/default.nix.
  2. Delete darwin/programs/onedrive.nix.
  3. If OneDrive was the only Darwin program module, remove ./programs from darwin/configuration.nix and delete darwin/programs/default.nix.
  4. Ask Michael to run the appropriate rebuild command.
  5. Remove compatibility symlinks under ~/OneDrive only after confirming they are symlinks.
Do not delete anything inside ~/Library/CloudStorage from scripts. Let OneDrive handle unsync, account removal, or reset flows.
